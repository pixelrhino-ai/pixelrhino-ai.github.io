Get started

Pull. Run. Create.

Use one exact model identity. VRhino acquires the fixed assets, verifies them, installs the local package, and runs it through the shared Native runtime.

LatentSync 1.6
vrhino pull vrhino/latentsync-1.6:1.0.0

vrhino run vrhino/latentsync-1.6:1.0.0 \
  --video input.mp4 \
  --audio driving.wav \
  --output output.mp4
Mode C

VRhino acquires supported upstream assets from their original sources, verifies them, and converts them locally where required. Pixel Rhino does not redistribute model weights or converted VRMs for Mode-C models.

How it works

One Native runtime. Multiple video models.

Model packages define what runs. VRhino provides the shared execution layer around them.

01 / PACKAGE

Frozen model graphs

Versioned model components and configuration tied to an exact package identity.

02 / PROGRAM

Bounded execution

Execution and sampling programs plus declared workflow inputs and outputs.

03 / RUNTIME

Shared Native layer

A single Native runtime executes supported packages on the qualified CUDA platform.

Self-contained

Bring the driver. Leave the stack.

You do not need to install:

  • Python
  • PyTorch
  • Diffusers
  • Conda
  • CUDA Toolkit
  • cuDNN
  • system FFmpeg
  • model-specific environments

A compatible NVIDIA GPU and NVIDIA Driver, sufficient VRAM and disk space, and Linux x86_64 remain platform requirements. Exact support is model- and profile-specific.
